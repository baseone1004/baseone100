블루스크린이 떴을 때 원인을 찾는 순서

파란 화면에 뜨는 정지 코드를 어떻게 읽고, 어떤 순서로 원인을 좁혀야 하는지 정리했습니다. 안정성 모니터와 덤프 파일 확인 방법까지 다룹니다.

작업하던 중에 화면이 갑자기 파랗게 변하고 재부팅되면 당황스럽습니다. 그런데 블루스크린은 윈도우가 더 큰 손상을 막으려고 스스로 멈춘 것이라, 원인을 알려주는 단서를 반드시 남깁니다. 그 단서를 읽는 방법만 알면 원인의 절반은 좁혀집니다.

화면에서 두 가지를 반드시 적어두세요

파란 화면에는 QR 코드와 함께 아래 정보가 뜹니다. 사진을 찍어두면 가장 좋습니다.

  • 정지 코드(Stop code) — CRITICAL_PROCESS_DIED 처럼 영어 대문자로 된 줄
  • 실패한 항목(What failed) — nvlddmkm.sys 처럼 .sys로 끝나는 파일 이름

이 중 실패한 항목이 가장 중요한 단서입니다. .sys 파일은 드라이버이고, 그 드라이버가 어느 장치의 것인지 검색하면 범인이 바로 나오는 경우가 많습니다.

화면이 너무 빨리 지나가서 못 봤다면 아래 "지난 오류 확인하기"로 넘어가세요.

자주 보이는 정지 코드가 가리키는 것

정지 코드주로 의심할 곳
IRQL_NOT_LESS_OR_EQUAL드라이버 충돌, 메모리
PAGE_FAULT_IN_NONPAGED_AREA메모리 불량, 드라이버
MEMORY_MANAGEMENT메모리 모듈, 램 오버클럭 설정
VIDEO_TDR_FAILURE그래픽 드라이버, 그래픽카드
DPC_WATCHDOG_VIOLATION저장장치 드라이버, 오래된 SSD 펌웨어
WHEA_UNCORRECTABLE_ERROR하드웨어 (CPU, 전원, 과열, 오버클럭)
CRITICAL_PROCESS_DIED시스템 파일 손상
KERNEL_SECURITY_CHECK_FAILURE드라이버 호환성, 메모리
INACCESSIBLE_BOOT_DEVICE저장장치 인식 문제, BIOS 설정 변경

코드만 믿지는 마세요

같은 코드가 전혀 다른 원인에서 나오기도 합니다. 코드는 어디부터 볼지 정하는 힌트로 쓰고, 확정은 아래의 로그와 검사로 하는 게 맞습니다.

가장 먼저 물어볼 질문: 최근에 뭘 바꿨나요

블루스크린 원인의 상당수는 "최근 변화"입니다. 아래에 해당하는 게 있으면 거기부터 되돌립니다.

  • 새 하드웨어를 장착했다 (메모리, 그래픽카드, SSD)
  • 드라이버를 업데이트했거나 자동으로 업데이트됐다
  • 윈도우 대형 업데이트를 받았다
  • 백신이나 가상 드라이브, VPN 같은 시스템 레벨 프로그램을 설치했다
  • 램 오버클럭(XMP/EXPO)을 켰다

특히 특정 게임이나 프로그램을 켤 때만 뜬다면 그 프로그램과 관련된 드라이버가 유력합니다.

지난 오류 확인하기 — 안정성 모니터

윈도우에는 언제 무슨 오류가 났는지 달력처럼 보여주는 도구가 있습니다. 잘 안 알려져 있는데, 원인 찾기에는 이벤트 뷰어보다 훨씬 보기 편합니다.

  1. Windows 키 + R → perfmon /rel 입력 → 엔터
  2. 날짜별 그래프가 뜹니다. 빨간 X 표시가 있는 날을 클릭합니다.
  3. 아래 목록에서 Windows 오류 항목을 더블클릭하면 상세 내용이 나옵니다.

여기서 블루스크린 직전 며칠 사이에 어떤 프로그램이 설치됐는지, 어떤 업데이트가 있었는지 함께 보입니다. 오류가 시작된 날짜와 설치 기록이 겹친다면 그게 원인일 확률이 높습니다.

더 자세히 보려면 이벤트 뷰어(eventvwr.msc) → Windows 로그 → 시스템에서 빨간 오류 항목을 확인하면 됩니다.

덤프 파일로 범인 찾기

블루스크린이 뜰 때 윈도우는 C:\Windows\Minidump 폴더에 .dmp 파일을 남깁니다. BlueScreenView 같은 무료 도구로 열면 어떤 드라이버가 문제였는지 목록으로 보여줍니다.

덤프 파일이 없다면 저장 설정이 꺼져 있는 것입니다. sysdm.cpl → 고급 탭 → 시작 및 복구의 설정에서 디버깅 정보 쓰기를 "작은 메모리 덤프"로 바꿔두면 다음부터 기록됩니다.

원인별 대처

드라이버가 의심될 때

가장 흔한 원인입니다. 최근 업데이트한 드라이버가 있다면 되돌립니다.

  1. 시작 버튼 우클릭 → 장치 관리자
  2. 해당 장치를 더블클릭 → 드라이버 탭
  3. 드라이버 롤백이 활성화되어 있으면 클릭

롤백 버튼이 회색이면 이전 버전이 없다는 뜻입니다. 이때는 제조사 홈페이지에서 안정 버전을 직접 받아 설치하세요. 특히 그래픽 드라이버는 최신이 항상 좋은 게 아닙니다.

메모리가 의심될 때

MEMORY_MANAGEMENT나 PAGE_FAULT_IN_NONPAGED_AREA가 반복되면 메모리 검사를 합니다.

  1. Windows 키 + R → mdsched.exe → 엔터
  2. 지금 다시 시작하여 문제 확인을 선택
  3. 재부팅 후 검사가 진행되고, 끝나면 자동으로 윈도우로 돌아옵니다

윈도우 기본 도구는 가벼운 검사만 합니다. 더 확실하게 보려면 MemTest86을 USB로 만들어 몇 시간 돌려보세요. 메모리를 두 개 이상 꽂았다면 하나씩만 꽂고 며칠씩 써보는 방법도 확실합니다. BIOS에서 XMP/EXPO를 켜두셨다면 꺼보는 것도 꼭 시도해 보세요.

시스템 파일 손상이 의심될 때

시작 버튼 우클릭 → 터미널(관리자)에서 차례로 실행합니다.

sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
chkdsk C: /f /r

마지막 chkdsk는 재부팅 후 실행되며 디스크 용량에 따라 몇 시간이 걸릴 수 있습니다. 시간 여유가 있을 때 하세요.

과열이나 전원이 의심될 때

WHEA_UNCORRECTABLE_ERROR가 뜨거나 부하가 걸릴 때만 꺼진다면 하드웨어 쪽입니다.

  • 본체 내부 먼지를 청소하고 팬이 도는지 확인합니다.
  • HWiNFO 같은 도구로 CPU·그래픽카드 온도를 봅니다. 게임 중 90도를 넘나들면 냉각 문제입니다.
  • 그래픽카드를 새로 달았다면 파워 용량이 부족하지 않은지 확인합니다.

윈도우가 아예 안 켜질 때

블루스크린이 반복돼 부팅조차 안 되면 복구 환경으로 들어갑니다. 전원을 켜고 윈도우 로고가 보일 때 전원 버튼을 길게 눌러 강제 종료하는 것을 세 번 반복하면 자동 복구 화면이 나옵니다.

여기서 문제 해결 → 고급 옵션으로 들어가면 이런 선택지가 있습니다.

  • 시스템 복원 — 문제가 없던 시점으로 되돌리기 (가장 먼저 시도)
  • 시작 설정 → 안전 모드 — 최소한의 드라이버로 부팅해서 원인 프로그램 삭제
  • 업데이트 제거 — 최근 업데이트가 원인일 때
  • 시작 복구 — 부팅 파일 자체가 깨졌을 때

마지막 수단은 마지막에

"이 PC 초기화"는 확실하지만 프로그램이 모두 지워집니다. 그전에 위 방법을 먼저 시도하시고, 초기화 전에는 반드시 자료를 백업하세요. 백업 방법은 윈도우 백업 3가지 방식에 정리해 두었습니다.

언제 서비스센터에 가야 하나

아래에 해당하면 소프트웨어로 해결될 문제가 아닐 가능성이 큽니다.

  • 윈도우를 새로 설치했는데도 계속 뜬다
  • BIOS 화면이나 윈도우 설치 화면에서도 멈춘다
  • 부팅할 때마다 다른 정지 코드가 나온다
  • 전원이 갑자기 꺼지거나, 탄 냄새 또는 이상한 소리가 난다

이 경우는 메모리, 저장장치, 메인보드, 파워 중 하나의 하드웨어 고장으로 보는 게 맞습니다. 증상이 나타난 날짜와 정지 코드를 메모해 가면 점검이 훨씬 빨라집니다.
